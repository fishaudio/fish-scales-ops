# Layer performance — sm_90 (NVIDIA H200)

Each table times one whole MLP or MoE block as a single CUDA-graph replay with
cold weights, at the H200's natural clock (no clock lock). ×fso is a
comparator's µs over fso's µs at the same M, so above 1 means fso is faster;
decode is M 1–128, prefill M > 128. Method: [`../README.md`](../README.md);
columns: [`README.md`](README.md); runs: [Environments of record](../README.md#environments-of-record).

## Comparators

Versions are those that `bench/env/h200.lock.json` pins; the environments block
shows what each run found.

| comparator | families | library and version | kernel or backend | configuration | precision |
|---|---|---|---|---|---|
| BF16 (torch) | A | torch 2.13.0 | two `F.linear` (cuBLAS) and an eager SwiGLU | cuBLAS's own heuristic | BF16 |
| sglang block-FP8 linear | A | sglang 0.5.20 with sgl-deep-gemm 0.2.0 | sglang's `Fp8LinearMethod` as its Qwen3 MLP runs it; its default backend on sm_90 is DeepGEMM, run with programmatic dependent launch on, as sglang serves it | DeepGEMM's own per-M heuristic (DeepGEMM has no tuned config files) | block-FP8: 1×128 activation and 128×128 weight scales, fp32 |
| cuBLAS scaled_mm block-FP8 | A | torch 2.13.0, cuBLAS 13.1.1.3 | `F.scaled_mm` with block-wise scales, which runs cuBLASLt's block-scaled FP8 GEMM; the activation quantize and the silu·mul are `torch.compile`d | cuBLASLt's own heuristic; cuBLASLt needs M to be a multiple of four, so the M = 1 and 2 rows compute zero-padded rows | block-FP8, fp32 scales |
| sglang triton BF16 | B, C | sglang 0.5.20, triton 3.7.1 | sglang's Triton `fused_experts`: routing, gather, both grouped GEMMs, SwiGLU and combine | apex's tuned Triton configs, the ones apex serves with when it does not use fso; where apex has no file for this Triton version, sglang takes apex's tuned file of an earlier one | BF16 |
| sglang triton FP8 w8a8-block | B, C | sglang 0.5.20, triton 3.7.1 | the same entry with block-FP8 weights | apex's tuned Triton configs, as above | block-FP8, fp32 scales |
| deep_gemm masked pipeline FP8 | B, C | sglang 0.5.20 with sgl-deep-gemm 0.2.0 | sglang's expert-parallel Hopper MoE path: DeepGEMM's masked grouped GEMMs between sglang's preprocess, activation-quantize and reorder kernels, with programmatic dependent launch on | DeepGEMM's own heuristic; measured on the decode band only | block-FP8 |

The MoE comparators run the routed layer only; Family C sets them against fso's
routed column.
