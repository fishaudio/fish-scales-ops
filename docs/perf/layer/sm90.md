# Layer performance — sm_90 (NVIDIA H200)

Whole MLP / MoE block per shape family as one CUDA-graph replay. Block
contents, FLOPs and the `model ms` convention: [`README.md`](README.md);
protocol, clock lock and M grids: [`../README.md`](../README.md). Tables are
generated from `tests/baselines/` jsonl — do not hand-edit rows.

Family A was re-measured on 2026-09-22 and its table comes from that run, not
from the 2026-09-03 session the other three sections come from. It was taken
on the local eight-H200 box, GPU 1 (`GPU-c20c737c-6d6f-ee29-67fc-6a6f37a19ccc`,
PCI `90:00.0`), under `nvidia-smi -i 1 -lgc 1980`: twenty of the twenty-one
clock samples taken during that bench read 1830 MHz and the twenty-first read
1815 MHz at 245 W, and the lock was released at the end of the session. The
library was a clean `ARCH=9.0a` build of commit `5add318`, run under the `.dev`
interpreter (Python 3.12.3, torch 2.11.0+cu130, system CUDA 13.2, NVRTC
13.2.78 — the same NVRTC binding the rows it replaces were taken with, which
`../README.md` section 8 explains is part of the sm_90 kernel). The run
directory is `/data/bench-runs/xarch_regress_20260922/h200/` and the baseline
file is a byte-for-byte copy of its `jsonl/pass1/qwen3_4b_mlp_fwd_sm90.jsonl`.

Why the section was re-baselined, and the one cell that is still unsettled.
The rows it replaces were measured on 2026-09-03 at commit `85d9c31` on a
different host, and one of them had drifted away from what this box now
produces: the M = 4096 BSFP8 cell held 665.63 µs, while the 2026-09-22 session
measured the same cell four times — twice on `5add318` and twice on its parent
`72516f4`, which changes no sm_90 dense code — and got 616.89, 674.45, 617.91
and 658.15 µs. The old row is therefore not a number this box reproduces for
either commit. It is equally true that the new row is not a settled number:
those four readings are bimodal with a 9.3 % spread, the two modes appear on
both commits, and the published value is the lowest of the four because the
convention is to publish pass 1 of two. The neighbouring M = 2048 and
M = 8192 cells of the same passes agree to better than 1.1 %, so this is a
property of that one cell rather than of the bench. Read the M = 4096 BSFP8
row, and the 992 TFLOPS and 22.21 model-ms figures derived from it, as the
fast end of a range that reaches about 674 µs, and do not accept or reject a
change on that cell alone. The per-cell numbers are in that run directory's
`delta_tables_noise.txt`, table N3.

Families B and C were re-measured on 2026-09-25 for the sm_90 grouped MoE
decode tuning (two resident CTAs per SM for the swap-AB kernel, register
reads of the weight scales, swap-AB activation tile 16 / 32 / 64 chosen from
the routed rows per expert) and their fso rows come from that run; the
comparator rows are the 2026-09-03 / 2026-09-04 rows they were published
with (same sgl venv, same protocol, not re-run). The session used the local
eight-H200 box, GPU 2, under `nvidia-smi -i 2 -lgc 1980` (busy samplers
reading 1830 MHz), the `.dev` interpreter (torch 2.11.0+cu130, system CUDA
13.2, NVRTC 13.2.78) and a clean `ARCH=9.0a` build of the commit that carries
this paragraph, against a run of `origin/master` (683ac8a) on the same card
the evening before. The run directory is
`/data/bench-runs/fso_sm90moe_2026-09-24/` (`proto_wt_base_*.jsonl` before,
`proto3_wt_*.jsonl` after); the baseline files are the after run's fso rows
spliced over the previous fso rows.

The comparator rows of Families B and C were taken on H200 GPU 0 of the same
