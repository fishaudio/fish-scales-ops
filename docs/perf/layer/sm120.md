Reading: MXFP8 is the faster fso path at every M on this device; both FP8
paths now sit at the quantization-limited cosine (the BSFP8 column read
0.984 before the 2026-09-05 weight-scale fix, see `../gemm/sm120.md`). Against the fused cuBLAS
chain the MXFP8 block is 3.1–4.4× faster at decode (M ≤ 32), 2.2–3.1× at
M = 64–128, and 6–10 % faster from M = 512 up; against the unfused cuBLAS
chain 1.9–5.9× at every M. These are the same ratios the July README quoted
for decode (5.4–6.3× unfused, 3.9–4.4× fused): the decode cells match the
July 5090 table within ±2 %. The July table's prefill rows (M ≥ 512) were
6–10 % faster than this run, but the July commit `a04c1b6` rebuilt and run on
this GPU on 2026-09-04 (`/data/bench-runs/layer_20260904/5090/mlp_fwd_qwen3_4b_a04c1b6_5090.jsonl`)
matches this baseline at every M (MXFP8 median +0.2 %, max +0.8 %; BF16
0.0 %), so the gap is drift of the carried-over table, not a code change.

Reading: on the routed layer fso is ahead of the triton FP8 path at M ≤ 16
(−4 % to −42 %), trails by +1 % to +13 % at M = 32–2048 (worst at M = 1024,
the masked-slab regime; M = 512 went from +8.7 % to +4.8 % with the grouped
cascade rule v5, see `../gemm/sm120.md`), and ties at M = 4096 (+1 %). The
shared expert costs a flat 12–19 µs up to M = 256, 33 µs at M = 512 (its dense
GEMMs run slower behind the 2-CTA/SM down tile; the block is still 5 µs
faster than before the rule) and 5–10 % of the block from M = 1024 up. The
M = 8192 fso cells need the slab-free (contiguous) sm_120 entry that does not
exist yet.
