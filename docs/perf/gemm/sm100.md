# GEMM performance — sm_100 / sm_103 (NVIDIA B300)

Status (2026-09-05): **block-FP8 1×128 support added, measurement pending.**
The dense block-FP8 path now runs on sm_100/sm_103 (1×128 / 128×128 UE8M0
scales expanded onto the MXFP8 tcgen05 tiers, same kernels and bytes as
MXFP8); grouped MoE remains sm_120/sm_90 only (M3). The Family A / B / C
tables below are to be measured on B300 with the protocol in `../README.md` (no clock
lock: `FSO_BENCH_WARM_MS=300`, rows labelled unlocked) once the host is
reachable — the 2026-09-05 attempt found both B300 hosts and their jump host
down. Earlier status (2026-09-03): pending decision. The old `perf.md` has B300 (sm_103)
rows for Family A and the cubic sweep, measured **without a clock lock**
("2032 MHz flat"), which breaks the cross-commit comparability rule in
[`../README.md`](../README.md) §5. Options at pick time:

1. Keep the file, publish B300 rows labelled `unlocked` with the warm-up
   protocol (`FSO_BENCH_WARM_MS=300`) stated in the environment block.
2. Keep the file with this status note only, until a reproducible protocol for
   the B300 exists.

Either way the file exists so that the sm_100/sm_103 target is stated, not
silently dropped. When filled, it follows exactly the structure of `sm120.md`
with the dtype columns BF16 (reference) and MXFP8 (1×32); there is no BSFP8
path on sm_100.
